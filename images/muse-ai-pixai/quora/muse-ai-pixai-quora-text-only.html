How Can You Use Muse AI to Make Anime Images with PixAI?

I ran this whole test on November 18, 2026, in Muse on the web (the cloud workspace version). Every step, setting and credit count you'll see comes from that session.

Short answer: Muse AI, Meta's personal AI agent, doesn't actually draw anything in this setup. It writes and runs a small script that sends requests to the PixAI API, and PixAI makes the images. Below is the exact route I took, from setup to a single test image to four more.

Some quick definitions. An API is a way for one tool to ask another to do something; here, Muse asks PixAI for a picture. An API key is the credential showing that the request is really yours. Think of it as a password that allows Muse to generate images through your PixAI account.

To follow along, you need access to Muse, a PixAI account with API access, and enough credits for one test and a small batch.

Why test the model on PixAI before using Muse?

[[IMAGE 07: 07_06_fig2_pixai_website_sample.jpg]]

Figure 2. My sample made directly on the PixAI website with Tsubaki.3, before involving Muse.

Before Muse got involved, I made this sample on PixAI with Tsubaki.3 and the very prompt I'd hand Muse later. That way I could judge the model and the prompt without touching API credits. One catch: website generations can still use your regular account credits.

After that, make sure the API actually supports what you want. At the moment, text-to-image, inpainting, outpainting, LoRAs and Tsubaki.3 reference images all work. Reference Pro, PixAI Edit and Edit Lite don't yet.

Then find your model version ID. Open the model page, click the version you want (V1 in my case) and copy the second ID in the URL, not the general model ID. For my Tsubaki.3 run, it was 2024383379556065549.

Why the fuss? A model ID points to the model in general. A model version ID points to one specific version, and that's the one the API needs for this request.

How do you connect Muse AI to the PixAI API?

Muse has two options with PixAI: operate the website like a person clicking around (browser actions), or call the API directly. The API is better for repeated requests, so I used that. Starting a new Muse chat on the web, I followed six steps and relied on PixAI's API documentation for the technical details. Steps 1, 2, 4 and 5 are messages I sent Muse word for word. You handle Step 3 yourself.

Step 1: Hand Muse the documentation

MESSAGE TO MUSE:

I want to connect you to the PixAI API so you can help me generate anime images.

Read the official PixAI API documentation first:

https://platform.pixai.art/en/docs

Also refer to the first API call guide:

https://platform.pixai.art/en/docs/quick-start/first-api-call

I want you to use the PixAI API directly, not operate the PixAI website through browser automation.

Explain the setup you need before making any API requests. Do not generate anything yet.

Muse answered that it had read both pages and sent no requests. It listed what it would need: the base URL, bearer-key authorization, create-then-poll calls, and my API key. It also proposed a secure link for the key, but I chose the file method in Step 3 because that's what PixAI's guide uses.

Step 2: Make a folder for the project

MESSAGE TO MUSE:

Create a folder named pixai-batch in your workspace.

Inside it, create a file named Sample.env.txt containing this line:

PIXAI_API_KEY=

Do not generate any images or make API requests yet. Tell me when the file is ready.

Step 3: Add the key on your own

Go to Library in Muse, then System files, then the pixai-batch folder, and open Sample.env.txt. Paste your key straight after the equals sign and hit save:

FILE CONTENT (PLACEHOLDER: INSERT YOUR OWN KEY)

PIXAI_API_KEY=YOUR_API_KEY_HERE

Your real key should never go into the Muse chat. Put it in the workspace file. That keeps it out of the chat transcript, but remember it's still saved in your workspace. Don't share that file, don't show what's in it in screenshots or logs, and don't put it in anything others can download. Treat it with the same care as any API credential.

Step 4: Rename it to .env

So what's a .env file? It's a config file where a script keeps things it needs, like API credentials. The script reads your key from there, so the key never appears in the code itself.

MESSAGE TO MUSE:

Rename Sample.env.txt to .env inside the pixai-batch folder.

Do not change or display the API key. Confirm that the file is saved in the correct location and that your script will be able to read the PIXAI_API_KEY environment variable from it.

PixAI's guide mentions that after renaming, the file may no longer show in Muse's web view. That's expected.

[[IMAGE 13: 13_12_step4_rename_to_env.jpg]]

Step 5: Ask Muse for the script

MESSAGE TO MUSE:

Inside the pixai-batch folder, prepare a Python script that connects to the PixAI API.

Requirements:

  • Read PIXAI_API_KEY securely from the .env file. Never print or expose the key.
  • Use the official PixAI API v2 endpoint for image generation: POST https://api.pixai.art/v2/image/create.
  • Authenticate using the Authorization: Bearer API_KEY header.
  • Allow me to provide a modelVersionId, prompt, negative prompt, aspect ratio and other supported generation settings.
  • Submit one image-generation task at a time.
  • Retrieve the task ID and check its status until it completes or fails.
  • Download the completed image into an output folder.
  • Log the task ID, generation settings, status and credit usage where available.
  • Do not automatically resubmit a request if it times out. Check the existing task first.
  • Before executing any generation request, show me the request details and wait for my approval.

Use the current official PixAI API documentation rather than guessing parameter names or endpoints.

Do not generate anything yet. First show me the script and explain how it works.

What the script does: it sends the prompt, receives a task ID, and keeps checking the task's status until the image can be downloaded. That repeated checking is what people call polling. PixAI's docs advise a gap of at least 1.5 seconds between checks, and they also say to download images soon, because generated media isn't stored forever.

How do you go from one image to a batch?

With the single image done, I kept the same character and changed only where she was. I started by asking Muse to write the prompts so I could review them:

MESSAGE TO MUSE:

I want to generate four additional illustrations using the same anime character from our successful test.

Keep these character features consistent:

  • Short silver bob haircut
  • Warm amber eyes
  • Black jacket
  • Red scarf

Create four different scene prompts:

  • The character walking through an autumn park.
  • The character sitting beside a café window on a rainy day.
  • The character standing on a snowy winter street.
  • The character watching the sunset beside the sea.

Keep the character description consistent and change the setting, lighting and pose as appropriate.

Use descriptive natural-language prompts suitable for the selected PixAI model.

Save all four prompts in prompts.csv inside the pixai-batch folder.

Show me the complete prompts before generating anything.

Read every prompt before you approve it. Watch for Muse quietly switching the hair colour or leaving out the scarf.

My test result:

How my test went: five requests, five images, no retries and no failures. PixAI charged 4,000 credits per image, 20,000 altogether, which matched Muse's estimate. Those numbers are for Tsubaki.3 at 864 × 1152, and they'll change with a different model or settings.

So, did the character stay the same? Mostly. The silver bob, amber eyes and red scarf show up every time, but there's drift: in the winter image the short coat turns into a zip-up jacket with trousers, and the scarf changes in shade and shape. Running a batch automates the work. It doesn't guarantee a consistent character.

What if something goes wrong?

I had exactly one problem, and I caused it: I gave Muse the model ID rather than the model version ID. Muse noticed before submitting, warning me that PixAI responds with 404 NOT_FOUND to a version ID it doesn't recognise. I swapped in the ID from the docs, and the rest ran with no errors.

Issues from the docs that I didn't hit myself:

  • Authentication fails. Each call must include the key in an Authorization: Bearer header. Confirm the key is pasted after the equals sign in .env without extra spaces, that the file is saved, and that your membership or API approval is still active.
  • A request times out. Don't resubmit right away. The task may already exist, and retrying could charge you twice. Check your balance and history, then ask Muse to continue the existing task by its ID.
  • The image didn't save. Generated media won't stay around forever, so have Muse download the files. PixAI's limits page also explains the cap on waiting tasks.

Quick FAQ

Can a non-programmer do this? Yes. Muse can write and run the Python script for you. You still have to get your API key, set up the workspace file and review each request before you approve it.

What's free, and what needs API access or credits? Trying a model on PixAI's website works with a regular account, though those samples may use account credits (see the pricing guide linked above). The API needs a key, through membership or an approved email request, and each API generation costs credits.

Will API images show in my public history? No. They're private and don't appear in your public generation history.
